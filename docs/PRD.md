# 物质纪元 Matter Age — V1.0 项目开发任务书

## 1. 项目目标

开发一款名为「物质纪元 Matter Age」的化学沙盒探索游戏。

参考 Little Alchemy 的物质合成玩法，以真实化学反应和物理变化为基础，结合自由探索、物质合成、实验动画、图鉴收集、关卡挑战、科学发现树和科技演进系统，构建具有教育价值与游戏性的科学探索产品。

产品采用移动端优先设计，同时适配 PC、平板和手机浏览器，支持 PWA 安装及离线运行。

V1.0 不需要服务器、用户注册或 AI API，所有游戏逻辑在本地运行。

## 2. 产品长期架构

产品规划三个难度等级：

- 简单模式：物质组合 + 反应条件 + 催化剂，无需考虑物质数量。
- 进阶模式：引入物质份数、化学方程式系数、反应物消耗和产物数量。
- 困难模式：模拟真实实验室流程，引入实验仪器、质量、浓度、温度、操作顺序和实验报告。

**本次仅开发简单模式，但数据结构和反应引擎必须为另外两个难度预留扩展接口。**

例如：

简单模式：

氢气 + 氧气 + 反应条件 → 水

进阶模式：

2份氢气 + 1份氧气 → 2份水

困难模式：

通过虚拟实验设备、计量系统和实验流程完成反应模拟。

三个难度必须共享统一的物质数据库与化学反应数据库。

## 5. UI 与视觉设计规范

### 5.1 整体风格

采用深色科学实验室风格，融合现代科学仪器、游戏化物质卡片和轻拟物视觉元素。

参考用户提供的小程序截图中的物质选择、实验台、条件操作和图鉴详情交互，但需要独立设计产品的视觉体系。

避免出现普通后台管理系统的视觉效果。

重点要求：

- 高信息密度，减少无意义留白。
- 清晰的页面信息层级。
- 实验台与物质仓库具有游戏质感。
- 物质图标采用统一的轻拟物或精细3D素材。
- 化学式规范展示上下标。
- 新物质发现具有明显的奖励反馈。
- 动画精致、简洁，避免过度炫光。
- 移动端支持单手操作。

### 6.3 实验反馈

执行实验后，系统根据结果显示：

成功：

- 播放对应反应动画。
- 展示所有生成物。
- 展示化学方程式或物理变化过程。
- 解释反应原理。
- 自动解锁首次发现的物质。
- 更新图鉴、发现树与成就。

失败：

- 提示当前组合未匹配已收录反应。
- 对已有明确规则的组合提示缺少必要条件。
- 允许重新调整物质。
- 不扣除自由探索资源。
- 不把数据库未收录的反应描述为现实中绝对无法发生。

首次发现：

- 金色描边。
- 新发现标签。
- 轻量粒子效果。
- 发现音效。
- 查看知识详情入口。

重复实验不重复发放首次发现奖励。

采用卡片式展示。

支持：

- 全部物质。
- 已发现。
- 未发现。
- 物质分类。
- 收藏。
- 搜索。
- 发现时间排序。

未发现物质使用未知图标或剪影，避免直接暴露所有答案。

物质详情包含：

- 中文名称。
- 英文名称。
- 化学式。
- 别名。
- 物质分类。
- 常温状态。
- 外观。
- 摩尔质量。
- 密度。
- 物理性质。
- 化学性质。
- 主要用途。
- 自然来源。
- 相关反应。
- 首次发现记录。
- 相关安全知识。
- 知识来源。

混合物、加工材料及状态类游戏道具允许部分字段为空，不得虚构摩尔质量或化学式。

### 6.5 科学发现树

使用 React Flow 构建物质关系网络。

功能要求：

- 节点拖动。
- 画布缩放。
- 节点详情。
- 已发现物质高亮。
- 未发现物质隐藏或显示未知节点。
- 已完成反应路径高亮。
- 按化学类别筛选。
- 查看某种物质的已知来源。
- 支持多条合成路径。
- 支持可逆反应和循环关系。

科学发现树应采用物质节点与反应节点组成的关系图。

不得将多个反应物之间的共同反应错误表达为任意单个物质均可独立生成产物。

知识关联与实际反应关系使用不同的连线样式。

### 6.6 目标挑战

第一版制作30个挑战关卡。

分为：

- 基础探索：10关。
- 组合实验：10关。
- 科学推演：10关。

每个关卡包含：

- 关卡名称。
- 任务描述。
- 初始物质集合。
- 可用实验条件。
- 目标产物。
- 实验次数限制。
- 提示机制。
- 最佳完成记录。
- 三星评价。

三星条件：

第一星：成功发现目标物质。

第二星：在规定实验次数内完成。

第三星：未使用提示。

挑战存档与自由探索库存隔离，避免通过自由探索直接跳过挑战。

第一版挑战不需要消耗具体物质数量。

### 6.7 科技演进

将物质发现与技术发展结合。

时代一：自然时代。

探索水、空气、木材、矿物等基础材料。

时代二：火与材料时代。

探索木炭、玻璃、陶瓷及石灰等材料。

时代三：金属时代。

探索铁、铜、锌、金属氧化物及合金相关知识。

时代四：化学工业时代。

探索酸、碱、盐和基础化工材料。

时代五：现代科技时代。

暂时作为后续版本预告，包括半导体、电池和高分子材料。

第一版时代系统仅实现解锁、进度展示、时代介绍和关键物质目标，不开发建筑、工业生产线或经营系统。

科技时代属于游戏化学习分类，不需要严格对应真实历史技术出现的年代。

## 8. 化学反应引擎

### 8.1 规则驱动

所有反应采用确定性规则匹配。

相同的物质组合、必要条件、催化剂和物质状态，在同一规则版本下必须得到一致的实验结果。

V1.0 不调用大语言模型动态判断化学反应。

### 8.2 匹配逻辑

实验执行流程：

1. 获取实验台所有物质。
2. 识别物质角色及状态。
3. 获取实验条件。
4. 获取催化剂。
5. 匹配已启用反应规则。
6. 校验必要条件。
7. 判断反应结果。
8. 播放对应动画。
9. 生成产物。
10. 判断是否首次发现。
11. 更新图鉴、发现树与成就。
12. 保存实验记录和游戏进度。

简单模式默认忽略化学计量系数。

普通混合反应默认不受物质添加顺序影响。确实具有顺序依赖的规则应显式定义。

如果多个规则满足同一组合，必须通过条件、状态或明确的优先级解决冲突，禁止随机选择科学结果。

### 8.3 反应数据结构

```

  "name": "氢气氧化生成水",
  "reactants": [
    {
      "substanceId": "hydrogen",

    {

      "coefficient": 1

  "simplificationNotes": [],

```

以上为数据结构示例，正式规则需要科学性审核。

### 8.4 化学计量预留

必须保留以下能力的接口：

- 化学式解析。
- 元素数量统计。
- 化学方程式配平验证。
- 反应物系数。
- 产物系数。
- 限制反应物计算。
- 剩余物质计算。
- 理论产量计算。
- 质量守恒校验。

即使第一版不使用份数系统，也必须确保数据能够支持后续进阶模式。

### 8.5 实验流程预留

困难模式需要预留：

- equipmentIds。
- procedureId。
- temperatureRange。
- pressureRange。
- concentrationRange。
- reactionDuration。
- operationSequence。
- safetyLevel。
- expectedObservations。

V1.0 只保留类型定义与必要接口，不实现真实实验室操作流程。

### 8.6 科学性约束

- 化学反应必须符合元素守恒。
- 涉及离子反应时需验证电荷守恒。
- 催化剂不得作为普通消耗型反应物处理。
- 物理变化与化学变化必须明确区分。
- 混合物不能强行赋予单一分子式。
- 简化反应需要标注简化内容。
- 不得将物质相关性直接定义为合成反应。
- 危险实验仅提供虚拟模拟和知识解释，不输出可在现实中直接执行的危险实验操作流程。
- 未经审核的规则不得进入正式发布数据集。

优先参考可靠的化学教材、权威化学数据库和科学教育资料。

建立独立的数据审核清单，记录每条规则的参考来源及待核验问题。

## 9. 实验动画系统

制作10类可复用动画模板：

1. 燃烧与能量释放。
2. 气泡生成。
3. 沉淀生成。
4. 溶解。
5. 结晶。
6. 颜色变化。
7. 汽化。
8. 凝固。
9. 熔化。
10. 冷凝。

每条反应可关联一个或多个动画模板。

动画支持：

- 颜色参数。
- 粒子参数。
- 持续时间。
- 动画阶段。
- 透明度。
- 产物展示。
- 音效。
- 跳过动画。
- 减少动态效果设置。

动画表现必须尽量符合对应反应的可观察现象。

V1.0 采用参数化视觉模拟，无需实现真实流体力学、热力学求解或分子动力学。

## 10. 提示系统

提供三级提示。

一级：提示相关物质类别。

二级：提示需要使用的物质。

三级：提示完整的游戏组合与条件。

自由探索模式允许使用提示。

挑战模式记录提示使用次数，并影响星级评价。

提示系统必须依据玩家当前拥有的物质和可执行规则动态生成。

禁止推荐当前无法完成的探索路径。

## 11. 成就系统

第一版至少实现12个成就。

例如：

- 第一次实验。
- 第一次发现新物质。
- 解锁10种物质。
- 解锁30种物质。
- 解锁全部物质。
- 完成首次挑战。
- 完成10个挑战。
- 首次获得三星。
- 解锁新的科技时代。
- 发现全部气体类物质。
- 发现全部金属类物质。
- 完成指定反应分类的探索。

成就采用数据驱动设计，支持后续增加。

## 12. 本地存档

通过 IndexedDB 保存：

- 已发现物质。
- 已完成反应。
- 首次发现时间。
- 实验历史。
- 挑战进度。
- 挑战最佳成绩。
- 科技时代。
- 已获得成就。
- 收藏物质。
- 玩家设置。

要求：

- 自动保存。
- 刷新页面恢复进度。
- 关闭浏览器后恢复进度。
- 支持 JSON 格式导出。
- 支持存档导入。
- 支持进度重置。
- 支持存档版本迁移。
- 重置前二次确认。
- 导入存档时校验数据合法性。

## 15. 测试与验收要求

### 核心功能

- 从初始物质能够逐步探索新物质。
- 实验台支持添加、删除及清空物质。
- 正确识别物质、实验条件与催化剂。
- 同一实验规则返回一致结果。
- 首次发现自动解锁图鉴。
- 重复实验不重复计算发现数量。
- 物理变化与化学变化正确分类。
- 不匹配的组合提供合理反馈。

### 内容质量

- 正式版本包含72种物质及状态。

- 化学反应通过元素守恒校验。
- 化学知识数据具有明确来源。
- 无虚构反应或错误化学式。
- 所有计划收集的物质均可获得。
- 所有正式发布规则完成科学性审核。

### 游戏功能

- 10种实验动画正常播放。
- 30个挑战关卡均可完成。
- 星级评价逻辑正确。
- 科学发现树支持交互。
- 四个科技时代可正常解锁。
- 至少12个成就正常触发。

### 工程质量

- TypeScript 类型检查通过。
- 单元测试通过。
- 端到端测试通过。
- 无阻断性控制台错误。
- 支持360px以上移动端宽度。

2. 将任务书写入 docs/PRD.md，并建立 AGENTS.md。
3. 建立可追踪的开发计划与任务清单。
4. 优先完成可运行的 P0 核心版本。

6. 在 docs/PROGRESS.md 中记录已完成事项、待完成事项、技术决策和发现的问题。
7. 不允许使用静态页面冒充已实现的游戏功能。
8. 所有按钮、菜单、筛选器和实验操作必须具有真实交互。
9. 核心游戏规则必须独立于 UI 实现。
10. 不使用 AI 动态生成未经验证的化学反应作为正式游戏结果。
11. 不因追求物质数量而降低科学准确性。
12. 对需要人工审核的化学内容明确标记，不将自动校验等同于科学审核。
13. 优先复用组件、动画模板和数据结构。
14. 避免为后续版本过度开发，仅保留必要接口。
15. 每个阶段保持项目可启动、可测试。
16. 不擅自改变产品定位、核心玩法及视觉方向。
